# Study Seat 原型设计说明

本说明对应 2026-10-29 定版。业务基线为团队已确认的需求规格说明书 V2.0；本次只交互演示核心场景，不声称完成需求说明书中的全部真实系统能力。

## 设计目标

为学生提供从查座、预约到签到使用的连续流程，为管理员提供规则、开放安排、临时关闭和记录追溯的 MVP。视觉沿用原有浅色与蓝色界面、房间插画和卡片布局；状态同时使用文字与颜色表达。

工具为墨刀和可执行 HTML/CSS/JavaScript 交互组件，AI 辅助修改与校验，由成员审核和确认。制作方式详见 [墨刀原型搭建与维护说明](墨刀原型搭建与维护说明.md)。

## 信息架构与关键流程

- 统一登录 → 学生登录 / 管理员登录。
- 学生：首页 → 自习室/日期/时段/座位 → 确认预约 → 我的预约 → 签到 → 暂离/返回 → 结束；个人中心展示账号及明确标注的统计示例。
- 管理：规则/开放安排 → 资源管理 → 关闭影响预览 → 确认关闭 → 关联预约和通知预览 → 重新开放 → 日志。
- 顶部导航提供返回与退出；返回保留必要条件，退出保留当前演示会话中已保存数据。

## 范围与限制

学生与管理端业务数据独立。通知不实际推送，登录不接入学校真实身份认证；没有服务端持久化、跨设备同步或真实多人并发控制。同一次打开中退出重登保留记录，刷新恢复初始场景。

管理端覆盖规则保存与版本、开放时段、关闭和重新开放、预约查询、详情与只读日志；不包含真实审批、设备控制或业务导出系统。

## 过程、困难与解决结果

| 问题 | 解决结果 | 设计收获 |
| --- | --- | --- |
| 学生与管理入口分离，登录后不易退回 | 使用统一登录宿主、独立角色表单及顶部返回/退出 | 导航与退出需要与主流程一起设计 |
| 返回可能丢失草稿、回到重复提交页 | 保存选座条件及导航来源；成功回执关闭进入预约列表 | 页面变化必须与业务状态同步 |
| 管理修改可能未经确认丢失 | 未保存编辑在离开时提示；关闭先预览再确认，关联记录保留返回来源 | 高影响操作应提供确认与可追溯反馈 |
| 原型与本地多轮迭代后不一致 | 复用确认后的交互，维护源文件和生成脚本并执行回归 | 原型、代码与文档应按同一版本管理 |
| 本地图表在布局就绪前初始化 | 监听容器真实尺寸变化并释放旧实例 | 脚本执行成功不等于界面显示正确 |

## 验证与来源

学生业务、管理业务、会话隔离、资源与界面检查的 67 项测试在代码同步阶段通过；实际操作了预约、签到考勤、退出重登、规则保存、关闭、关联返回与重新开放。本轮新增资料导出检查后总计 69 项自动测试通过。测试的实际范围和工具环境日志说明见 [墨刀同步记录](墨刀同步记录.md)。

本项目基于同组同学的 [studyseat-prototype 仓库](https://github.com/coisiniand/studyseat-prototype) 迭代，保留原学生界面基础，再补齐管理端和统一导航。个人贡献比例、真实工时及团队协作应由团队如实确认。
